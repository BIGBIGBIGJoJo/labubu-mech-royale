# Pursuit fire plan

Written before implementation, based on exact best39b6d50. The user now requests fast pursuit of the nearest enemy, maximum available firepower, reload when no enemy is near, and healing at low health when no enemy is near. Mechs and NPCs have equal target priority. Near means a held weapon's usable geometric range, independent of magazine, cooldown and current aim. This replaces the earlier selective-fight restrictions.

## Concrete changes

1. Add `Combat.plan(..., allow_partial_reload=True)`. Orchestration passes false whenever any current enemy is geometrically near. It guards both baseline partial-reload paths: idle/allow_fire-false top-up and the invalid-solution gun-ammo<=3 top-up. An empty magazine still reloads, and a reload already in progress is not canceled. Default true preserves existing call semantics. The current invalid-solution branch otherwise starts an avoidable reload while turning toward a nearby occluded or temporarily unreachable target.
2. Add pure `Combat.geometrically_usable(obs, target, line_clear=None, deadline=None) -> bool | None`. It uses current live weapon stats, cube-scaled body/muzzle geometry, pitch envelope and range. `line_clear=True` reuses root's current center/upper-body LOS and avoids duplicate direct map rays; this is a conservative danger envelope, not proof that the barrel has a firing path. `None` checks world segments here and `False` rejects a blocked actor. Mortar always checks its actual arc. The query ignores cooldown, ammo, energy and present torso yaw so near does not oscillate during ordinary weapon cycles. It checks direct weapons before the costlier mortar arc, short-circuits on the first usable weapon, and does not alter laser/mortar latches. Root supplies a shared proximity deadline; an interrupted query returns `None` (unverified), which root must treat as near, never as quiet. Root scans current actors and owns target priority/recovery; no stale aim target is invented. For gun geometry this is the current body envelope, not a claim that a moving target's future intercept is guaranteed. Final Combat firing retains its independent map/body/readiness checks.
3. Preserve the existing two-slot scheduler: available gun/lightning fire can accompany charging; charged/lethal laser release owns shared aim; mortar receives its existing bounded.3 s aim commitment. Every trigger retains readiness, actual next-tick torso slew, body/pitch/world geometry and self-blast constraints. Maximum firepower means valid emissions from both slots where their aim is compatible; blindly holding both would prematurely fire the laser or launch a mortar along gun pitch.
4. Correct the verified lightning cone interpretation from half of30 degrees to the documented within30 degrees of aim yaw. This removes an unsupported15-degree restriction during pursuit/turning. Add20/29/31-degree actual-next-yaw tests and maintain range, energy reserve and line-of-sight checks. Other weapon tuning remains unchanged.

## Root-policy integration

Orchestration selects the nearest current mech/NPC. It uses one shared near predicate for healing and partial reload. Low HP alone must not set Combat emergency while an enemy is near, because baseline `emergency=urgent or recover` suppresses fresh laser charges and mortar commitment even when the gun is allowed. Actual urgent zone escape retains emergency authority and existing charged-laser release behavior. A missing/out-of-range/blocked nearest target can still be pursued while Combat withholds invalid shots. The movement module owns pursuit bands and boost choices; none of those preference distances redefine weapon range.

Movement proposals (gun70 m, gun+laser80 m, NPC35 m, lightning live range minus6 m) are unvalidated design choices, not proven damage-optimal distances. The controller still checks large-self/small-target pitch limits and mortar splash clearance. Laser charging halves movement speed and cannot be canceled: releasing below minimum commits a beam once minimum charge is reached. We do not introduce a new urgent minimum-charge exception or blanket rapid-release policy. Mortar `drain`45 is concussion inflicted on a blast victim, not a launch energy cost; do not invent an energy requirement.

## Validation before freeze

- Partial reload disabled with idle target, allow_fire false, and invalid solution at1–3 rounds; zero ammo still reloads in each state; no enemy/default calls preserve top-up behavior.
- Near remains true with empty/reloading gun, cooling laser and misaligned torso; false outside upgraded range or behind blocking geometry; small NPC/large self pitch and scaled muzzle cases; mortar arc/self-blast constraints; no observation or latch mutation.
- Both compatible gun+laser and gun+lightning use their slots, charged laser retains aim precedence, mortar commitment remains bounded, urgent escape still suppresses fresh charge.
- Lightning actual-next-yaw20/29 degrees fires,31 degrees does not; energy/LOS gates remain.
- Existing Combat tests plus focused pursuit tests. Measure multi-actor near-query cost on the official map and report any unresolved budget concern to root; no official score improvement is claimed from unit tests or private rank.

The correction is intentionally bounded to the user-requested fire/reload behavior and one documented cone error. Later ballistic/own-motion changes from lower-scoring branches are not silently ported into the exact-best baseline.

## Implementation validation

The bounded visibility integration adds `Combat.range_envelope_possible(obs, target) -> bool`: no map rays or arc solves, no mutation, and no readiness/ammunition/energy gate. It conservatively includes own barrel extension and target body radius using live cube dimensions, and leaves mortar reach unverified/possible. Root uses this only for actors whose center/top visibility could not be assessed inside its shared LOS budget. An unknown actor with possible range vetoes quiet healing/partial reload and marks assessment incomplete; a proven out-of-range actor need not do so. This helper never grants firing permission. Existing final Combat geometry remains unchanged.

35 existing Combat tests and27 new pursuit Combat tests pass. The new tests cover both partial-reload gates, empty/in-progress reloads, near invariance across readiness/energy/aim, live range, large-body/small-NPC pitch, LOS reuse versus actual blocked firing, mortar self-blast/arc, immutable state, compatible two-slot firing, urgent laser suppression, full lightning cone, interrupted near queries and the conservative no-ray range envelope.

The host-only official-map proximity benchmark uses40 recorded locations and27 synthetic actors per case, with the caller's2 ms shared deadline. All27 out-of-range direct actors finish in at most.422 ms; all27 known-blocked actors at most.025 ms; all27 pitch-invalid actors at most.996 ms. A directly usable actor short-circuits at the first candidate (max.153 ms). Artificial mortar-heavy cases reach the shared deadline: maximum2.468 ms including a single in-progress map ray;67/80 are unverified and conservatively treated as near. These cases deliberately supply LOS to stress arcs, so they do not estimate real-game frequency. No query exceeds2.468 ms in this240-case sample; this is a measured sample, not a universal wall-time guarantee.
